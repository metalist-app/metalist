# Note Content Formatting (Meta Tags)

Renamed 2026-10-28, before launch, so each name says what the note is in words people know: `@highlight`, `@ai` (a saved AI chat answer), `@bullets` and `@numbered` replace four older names. Each vault is converted once when its notes are first read after unlock: every note's tags and proposed tags and every search context's search (`app/services/meta_tag_renames.py`, recorded in `namespace_content_migrations`, so a restored older backup is converted again; each note keeps its updated time). ## Overview
- Note content is stored as HTML (`notes.content`).
- The server can apply **view-only** formatting transformations based on **meta tags** (tags starting with `@`) in the tag bar (`notes.tags`).
- **Editing vs viewing:**
  - When a note is being edited by the current client, the server sends **raw content** so all delimiters remain visible.
  - Otherwise the server sends **rendered view HTML**, which may consume delimiters and wrap regions in styling spans.
  - Note references (`[[UUID]]`) are rendered only in view mode.
- `⌘ + U` removes formatting and inline imagery from the selected range, or from the entire active note when no text is selected. The editing context menu's **Remove Formatting** uses the same selection behavior. Range removal deletes intersecting inline images and splits scoped delimiters around the selection so the surrounding text keeps its styles. Fully selected headings and other presentational blocks become neutral blocks; their line boundaries and links remain intact, and unselected blocks retain their formatting. Leading/trailing whitespace inside a copied heading does not need to be selected. Partial block selections use plain-text spans to override inherited heading/block typography only on the selected words; surrounding text keeps its formatting and no extra line breaks are introduced. Those spans survive saving and follow the note-size preference. Whole-note removal strips rich-text HTML and all inline images while preserving links, and removes the visual and renderer meta tags offered by Add Style. It trims blank lines from both ends and reduces internal blank-line runs to at most one empty line (two line breaks); ordinary single line breaks remain unchanged. Visible line and paragraph breaks remain intact, including literal newlines previously rendered by `white-space: pre-wrap` formatting.
- A delimiter remains when another surviving wrapped tag still uses the same bracket type and depth. Semantic tags such as `@todo`, credential tags, comments, and ordinary tags are preserved.
- The actively edited note's context menu exposes the same selection-aware operation as **Remove Formatting**, directly beneath **Add Style**.

## Embedded Note References
- Syntax: `[[UUID]]` (an older `![[UUID]]` to a note reads the same).
- In **view mode**, a note whose only content is the reference is an embed: it shows the referenced note and its subtree in place, tinted, drawn as the main tree draws notes. With other content in the note, the reference is a link (`title ↗`) in its line.
  - Each note in an embed shows its saved collapsed/expanded state, with its own arrow where it can collapse; the holder folds as its source (see `docs/ui/references.md`). An exported file starts the same way, with working arrows; a print shows the whole subtree.
  - Missing UUIDs render a "missing reference" marker.
  - Circular reference chains render a "circular reference" marker and stop at that point.
- In **edit mode**, the token remains literal text (`[[UUID]]`).
- Full reference behavior and shortcut workflow: `docs/ui/references.md`.

## Links In View Mode
- Bare `http://...` and `https://...` text in rendered note content is auto-linked in view mode.
- **Every web link looks the same** (agreed 2026-10-26): the site's icon, the link's text, then ` · domain`. A bare address (alone on its line or inside a sentence, pasted URL-only anchors and Markdown URL-only links too) shows its fetched title as its text, once the server has one. A link with its own text (a pasted link with its label, a Markdown `[text](url)`) keeps that text and gets the icon and domain; its page's title is never fetched, only its site's icon. Text that already is the domain is not followed by it again; a link with no text (a linked picture) and links that are not web pages (`mailto:`, in-page `#` links, note references, files) stay as they are. Each render asks once per link (`_LINK_FETCHES_IN_RENDER`; a note with footnotes is linked twice). `tests/unit/test_link_decorations.py`.
- **No repeated site under a link to it** (agreed 2026-10-28): a web link whose site any of its note's ancestors links to, anywhere in their text, shows its text alone, underlined in link color, with no icon and no ` · domain` (a video's chapter links under the video note: `0:57 Starter`, not `0:57 Starter · youtube.com` nine times). The same site is the same domain, whatever the subdomain (`www.`, `m.`, `music.youtube.com` and `old.reddit.com` count as `youtube.com` and `reddit.com`; `bbc.co.uk` keeps its country suffix), and `youtu.be` counts as `youtube.com` (`link_titles.site_of_url`). A link to another site keeps both.
  - The ancestors count where they are shown above the note: in the list, inside an embed (its first note has nothing above it, its children have it), in full screen and floating windows (from the note opened), and in downloads and prints, which look as MetaList does. A note drawn on its own keeps every icon and domain: an embed's first note, a link's preview, a preview card. The note holding an embed and that note's ancestors don't count for the embedded notes.
  - An ancestor a search hides still counts. Removing the ancestor's link or moving the note elsewhere brings the icon and domain back on the next view. The domain is left out of the drawing, so find doesn't match it either.
  - Implementation: `content_formatting.showing_sites_above()` (the sites linked above the note being drawn) leaves out `_link_icon_html()` and `_link_domain_html()` for them; `sites_linked_in()` reads a note's sites. Callers: `snapshot._sites_shown_above()` (ancestors, memoized per record; the sites are in the render cache key), `embedded_references` (a referenced note starts with none, embedded children add their parent's), `note_fullscreen`, `html_export`. Tests: `tests/unit/test_repeated_link_sites.py`.
- Compact note-reference previews reuse the same standalone URL rule, including collapsed embeds and expanded embed source links.
- An address whose title is unknown, failed or unsupported renders as a raw URL link. Failed standalone lookups can expose their status/retry timing through the browser's normal hover tooltip.
- Lookups are polite to each site (the hostname without `www.`): one request to a site at a time, at least 2 seconds apart, so a note full of links to one site does not trip its rate limit. A site that answers HTTP 429 (too many requests) is left alone for its `Retry-After` time (1 minute to 6 hours; 10 minutes when it gives none), and lookups of its other links wait until then without being recorded as failures. The rate-limited link itself is retried after 10 minutes, 1 hour, 6 hours, 1 day, then weekly.
- **Link icons** (`app/services/link_icons.py`; the AI's help: `help-formatting.md`): a titled link shows its site's icon before the title, as tall as the text and centred on it, 0.3em before it, in a note (open or collapsed) and in a compact reference alike. The icon appears once both the title and the icon are known; a site without one shows the title alone, with no placeholder. In the dark theme the icon sits on a small light tile (`#e9edf2`), since most icons are drawn for light pages.
  - One icon per site (origin: scheme, host and any non-default port), fetched once by the server, never by the browser: the icons the site's front page declares (`rel="icon"` or `shortcut icon`, the smallest of at least 32 pixels first, then those without sizes, then smaller ones; `apple-touch-icon` after them; icons declared only for a dark colour scheme last, since the dark theme's tile suits a light icon), at most three, then `/favicon.ico` (where the front page forwards to). The oEmbed sites below go straight to `/favicon.ico`. Requests take the title lookups' guards (public addresses only, pinned connections, 5 redirects), timeouts and per-site turns; an icon over 1 MB is refused. Sites often declare a full-size logo (a 454 KB PNG, a 4501-pixel square), so the limits are generous: only the shrunk PNG is kept.
  - An icon must decode as BMP, GIF, ICO, JPEG, PNG or WebP of at most 25 million pixels, or be a self-contained SVG (below) (from an ICO, its smallest image of at least 32 pixels); it is kept as one 32-pixel square PNG centred on transparency, shown inline as a `data:` image. Shrinking a big one takes under a tenth of a second and about as much memory as the decoded image (about 100 MB for a 20-million-pixel RGBA logo), briefly, once per site: it is box-reduced a band of rows at a time, and one image is shrunk at a time.
  - **SVG icons** (agreed 2026-10-29; many sites declare only one, such as `rea.tools` and `*.github.io` pages): the declared SVGs are tried after the declared bitmaps and before `/favicon.ico`, including one written into the page as a `data:image/svg+xml` address (no request). The server draws it with resvg (`resvg_py`) at 64 pixels, then shrinks it like any icon; the SVG itself is never kept or sent to the browser. System fonts are loaded, so an emoji favicon (`<text>🦊</text>`) draws. Refused (no icon, `invalid_image`): over 100 KB, not UTF-8 or not well-formed XML, a `DOCTYPE`, entities, `<?xml-stylesheet?>` or `@import`, an `image`, `feImage`, `script` or `foreignObject` element, any `href` not to the SVG itself (`#id`), any CSS `url()` not to `#id`, or a drawing with nothing visible. resvg reads files an SVG names (`<image href="/path">`, found 2026-10-29): that check keeps a site from reaching files on the computer MetaList runs on, and relative paths resolve in an empty folder besides. Implementation: `link_icons._svg_icon_png()`; tests: `tests/unit/test_link_icons.py`.
  - A site recorded without an icon before SVG icons were drawn (`_SVG_ICONS_DRAWN_SINCE`, 2026-10-29) is asked again the next time one of its links is shown, not after the usual wait.
  - A site without a usable icon records why its own icon failed (`too_large`, `invalid_image`, …), not the `/favicon.ico` tried after it.
  - A site without a usable icon is asked again after 1 day, 7 days, then every 30 days, only when one of its titled links is shown. A found icon is kept. `Retry Failed Link Titles…` leaves icons alone. An icon arriving refreshes the view like a title (the link-title revision).
  - Stored in the `link_icons` table, origin and icon encrypted like link titles (`docs/security/README.md`); rewritten when a password is added or removed, cleared from memory on lock, loaded and unlocked with the titles.
- Lookups only run when a link is displayed, so failures in notes that are rarely viewed wait indefinitely; the command palette's `Retry Failed Link Titles…` asks all of them again (`docs/ui/command-palette.md`).
- Title fetches are server-side background work; note rendering never waits on network I/O, and edit mode always shows the original stored URL. When background fetches complete, the server increments a link-title revision exposed by `/api2/auth/status`; the browser polling loop batches those changes and triggers a view refresh so newly resolved titles appear without a manual page reload.
- While editing, the existing 500 ms inactivity check observes the current draft and requests title prefetch after it remains unchanged for at least 600 ms (typically 1–1.5 seconds after input). `POST /api2/notes/link-titles/prefetch` uses the same view-formatting eligibility and background fetch cache without saving the draft or replacing editor HTML. Identical drafts are requested once per editing session; typing and pasting restart the pause.
- Leaving edit mode always completes a view refresh, including when another view request is in flight. Title revision refreshes defer while editing, then require a refresh so slower lookups appear automatically without disturbing typing.
- Links to Reddit, YouTube (including `youtu.be`), Vimeo, TikTok, Spotify and SoundCloud first ask the site's public oEmbed service, the preview service those sites provide, for the title. It gives the real post or video title where the page itself is blocked for automated requests or built by JavaScript. The request is paced like any request to that site. A link that forwards elsewhere (a Reddit share link such as `/r/…/s/…` forwards to its post) is also looked up at each address it forwards to. When the service has no usable answer (not a post or video, removed, private), the page is read as for any other site. X is not included: its oEmbed service returns no title.
- Otherwise, title extraction is generic HTML metadata parsing (`og:title`, `twitter:title`, `meta name=title`, `itemprop=name`, and `<title>`).
- A title that is only the site's name ("Reddit" for reddit.com, "YouTube", "BBC" for bbc.co.uk, or the domain itself) says nothing the domain does not; it is treated as no title, so the link shows its URL (Reddit's URLs name the subreddit and post). Reddit's generic page titles ("Reddit - Dive into anything") count as no title too. Saved ones are cleared at the next login.
- Challenge/interstitial titles such as verification, browser-check, or access-denied pages are treated as `no_title` and cleared from existing cache rows on startup/login so they fall back to the raw URL instead of being displayed as valid page titles. So are login, consent and not-found pages, also when the site adds its name: a title is split at the site-name separators (`|`, `·`, `–`, `—`, and ` - ` with spaces) and is not a real title when a part is only a phrase such as "Sign in", "Log in", "Sign up" or "Page not found" ("Sign in - Google Accounts", "Log in | LinkedIn"), or when it contains "before you continue" (YouTube's consent page) or "log in or sign up". Titles that merely mention these words ("How to sign in to Gmail") are kept.
- Existing rendered anchors are normalized to open in a new browser tab.
- Clicking a rendered note link (including its title/domain spans) leaves the note in view mode; links do not initiate note dragging. Links inside the active editor keep normal editing behavior.
- Internal hash-style anchors used by MetaList note-reference UI are left unchanged so in-app reference navigation still works.

## Content Wrappers
- Wrappers in note content are semantic markup regions:
  - `{{...}}`, `[[...]]`, `((...))`
  - Depth 1–3 is supported (e.g. `{{{...}}}`).
- Wrappers in content are **only consumed/hidden** in view mode when there is a matching *scoped wrapper tag* in the tag bar.
- If there is **no matching scoped wrapper tag**, wrappers are treated as literal text and remain visible even out of edit mode.
- When a matching `[[...]]` scoped wrapper tag is active, `[[...]]` is formatting syntax, except that `[[UUID]]` containing exactly a note or file UUID is always a link. `![[UUID]]` still renders as an embedded reference.

Scoped wrapper tags do not need to be meta tags:
- Example: tag bar `[foo]` causes all `[...]` regions in the note to render without the brackets in view mode.

## Meta Tags

### Global meta tags
- A meta tag with no wrapper applies to the entire note content.
- Example: `@red` makes the whole note red.

### Scoped meta tags
- A wrapped meta tag applies only to content wrapped with the same bracket **type** and **depth**.
- Examples:
  - Tag bar: `{{@monospace}}` → applies to `{{...}}` regions.
  - Tag bar: `[[[@red]]]` → applies to `[[[...]]]` regions.
- Depth must match exactly:
  - `[[...]]` matches `[[@tag]]`
  - `[[...]]` does **not** match `[@tag]` or `[[[@tag]]]`
- A selected scope may cross multiple editor blocks/lines. View rendering closes and reopens visual formatting spans at each block boundary so every selected line keeps the style without producing invalid HTML.

Multiple tags can appear inside the same wrapper token (space-separated), and all recognized meta tags apply:
- Example: `{{@red @monospace}}`

Other (non-meta) tags may also appear inside wrapper tokens (e.g. `{{foo bar}}`). Those tags are currently inert for formatting, but the presence of the wrapper token still enables consuming the matching content delimiters in view mode.

### Nesting
- Scoped regions can be nested within each other.
- If the tag bar contains multiple scoped meta tags, the rendered view content may contain nested spans.
- Crossing basic-format scopes are supported as well. A range such as `[[bold {both]] italic}` is rendered by closing and reopening the crossing style so the overlap becomes valid nested HTML.

## Initial meta tags
- `@monospace`: renders the (scoped) region using a monospace/code font.
- `@red`: renders the (scoped) region in red.
## Basic formatting tags
- `@heading`: increases font size and weight.
- `@quote` (2026-10-31): a quote as Markdown draws one, indented with a grey bar at its left (lighter in the dark theme), in Add Style as **Quote**. On a whole note it quotes all of it; folded, the note shows its first line with the bar. Scoped (`((@quote))`, any bracket and depth) each region is a quote block: a region mid-line breaks out onto lines of its own, the text before and after it on lines of their own, and a region over several lines draws one bar. The line break right after a region is dropped, since the block's end already ends its line (`_without_breaks_after_quotes`). The Obsidian import writes quotes and callouts with it (`PLAN.md`). Tests: `test_content_formatting.py`.
- `@bold`: renders bold text.
- `@italic`: renders italic text.
- `@strikethrough`: renders struck-through text.
- `@serif`: renders with a serif font.
- `@green`: renders text in green.
- `@blue`: renders text in blue.
- `@grey` (or `@gray`): renders text in grey.
- `@highlight`: adds a fluorescent-yellow, slightly irregular marker stroke behind the text.
- Ontology implication rules can add these formatting tags implicitly (e.g. `bug => @red`).

## Footnotes
- `@footnote` is scoped only: an unwrapped `@footnote` has no effect on the whole note.
- Example: content `blah{{foo}}` and tag bar `{{@footnote}}` renders `blah` with a superscript `[1]`, followed by an always-visible **References:** section containing `[1]: foo`.
- Numbers follow first appearance within each note and update automatically. Identical footnote text reuses its first number and reference row, including across scopes with different visual styles; the first occurrence determines the reference styling. Links or images with different destinations remain separate references.
- Footnote and AI-reference sections use smaller body text, regular-weight reference numbers, and lighter headings; inline citation numbers use medium-weight superscripts.
- Clicking a superscript smoothly scrolls to and focuses its reference in that same rendered note. Collapsed previews retain the first line’s footnote markers; clicking one expands the note before scrolling to its reference. The References section stays hidden while collapsed. Reduced-motion preferences disable the smooth animation.
- URL-only link labels in reference bodies use the existing cached `title · domain` display, including plain URLs, Markdown links, and pasted HTML links. Missing titles enqueue the usual background fetch and appear on a subsequent view refresh when available; custom link labels remain unchanged.
- An `@markdown` note's own footnotes (`[^1]`, `^[text]`) join the same list (Markdown meta tags below).
- Reference bodies preserve rich content and render Markdown links without requiring `@markdown` on the whole note. Scoped visual styles and selections across paragraphs are supported.
- Spaces immediately before footnotes are hidden in view mode: `and even {{moar stuff}}` renders as `and even` immediately followed by its superscript. For scopes mixed with ordinary text, line breaks and spaces after the marker remain intact.
- A line or paragraph containing only a footnote attaches its marker to the preceding visible paragraph. Consecutive footnote-only lines attach to the same paragraph; empty continuation blocks of long footnotes are removed. The following prose keeps one paragraph break, without accumulating empty lines. A footnote at the start of a note keeps its marker in place. The original line and paragraph layout remains unchanged while editing.
- While editing, all original content, spaces, and delimiters remain visible; generated numbers and References are never stored in the note.
- Select text while editing, then right-click → **Add Style → Footnote**. The action reuses an existing dedicated footnote scope when available. It is hidden without a selection.
- **Remove Formatting** also removes footnote tags/scopes and leaves their original text in place.

## Size meta tags
- `@size=0.1`, `@size=0.25`, `@size=0.5`, `@size=0.75`, `@size=1.0`, `@size=1.25`, `@size=1.5`, `@size=2.0`, and `@size=3.0` scale the whole note or matching scoped region in view mode without modifying image bytes or file metadata, up to the width of the note or embedded note it is in and never past it. Any image shrinks to fit that width, keeping its shape, in MetaList, exports and prints. A size is a fraction of the size that fits: an image wider than its note fills it at `@size=1.0`, and every smaller step shows as that fraction of the note's width.
- Inline-image context menus expose **Make Bigger**, **Make Smaller**, and **Reset Size** in both edit and view modes. View mode refreshes immediately; edit mode shows the updated raw delimiters and numeric tag, keeps the caret where it was, also right beside an image (a caret after an image stays after it and after the `}` a size adds; one inside a removed scope lands beside its image), and ⌘Z undoes the size first. The saved caret counts each image as one unit (`contentTextOf` in `viewport-hold-service.js`), and the resize maps it across the added or removed braces only (`contentPositionsAcrossResize` in `context-menu-events.js`); tests: `scripts/browser-image-resize-caret-regressions.mjs`. While editing, images show at their size too (as outside edit mode, images only): at once after a menu resize, and about half a second after typing a size tag or a brace pauses; the display zoom is never saved. With the pointer on a picture or diagram in the list, **⌘+** and **⌘−** (Ctrl+ and Ctrl− off a Mac) do the same as Make Bigger and Make Smaller, viewing or editing, again and again without moving the mouse; the menu shows them beside the two items. Anywhere else the keys zoom the page as usual. The key is known by its place on the keyboard (`event.code`), and the picture by where the pointer last was (`handleImageResizeShortcut` in `context-menu-events.js`); tests: `shortcutCase` in `scripts/browser-image-menu-regressions.mjs`.
- Stored image-file embeds expose the same actions in view mode. Reset removes `@size` and removes delimiters only when no surviving tag owns that scope.

## List meta tags
- `@bullets`: renders the note's immediate children as a bulleted list in view mode.
- `@numbered`: renders the note's immediate children as a numbered list in view mode.
- Only direct children are affected (grandchildren are not).

## Credential meta tags
- `@username`: renders the note content as a credential row in view mode: a user icon (hovering it says Username), then the value and a copy button ("Copy username"); no eye. Like `@password`, the note is never sent to the AI, and exports and prints hide it unless the user includes it.
- `@password`: renders the note content as a credential row in view mode: a lock icon (hovering it says Password), then `••••••••` (eight dots, whatever its length), an eye and a copy button. The real value is never the page's text until its eye is clicked: it is only in the value's `data-copy-value`, so it can't be selected, found or read aloud, and a screen reader says "Hidden password" (the maintainer, 2026-11-03: before, it was its text, blurred, which hid it from a glance but not from the page). The eye shows the value in a monospaced font (to tell `l`, `1` and `I` apart) until the next thing you do: the eye again, a click anywhere else (its copy button too, after copying), any key (Escape too), or leaving the window (the maintainer, 2026-11-03); no timer, and it stays shown while the view redraws under it. Showing one hides any other: each row has its own eye (the note's own row, a link to it, an embed, a floating window). A reload or logging out (locking) hides it too. It hides once a press is released, so what the press is on doesn't move first. The value sits in a space 24 characters wide, the same for every password, monospaced: showing it moves neither the eye nor the copy button, and the space says nothing of its length; a longer password wraps inside it, the icons staying on its first line (the maintainer, 2026-11-03). The buttons are named "Show password"/"Hide password" (`aria-pressed`) and "Copy password"; Enter and Space press them. Editing the note shows the real text. A floating window's title shows the dots. Exports and prints hide it as `••••••••` unless the user chooses to include passwords there, which then shows them as text. A link to an `@password` or `@username` note (a reference among other text) is this row, buttons and all; the rest of the link goes to the note; exports, prints and the AI show `••••••••` (2026-10-26). `app/services/credential_display.py` (`CredentialDisplay`: dots in MetaList, hidden, or shown in an export).
- Copy buttons: Every copyable value (`@copyable`, `@username`, `@password`) has a copy button, a clipboard icon that is always there, faint, darker on hover; a click copies the value and the icon turns into a check mark for a moment. Clicking the value itself copies nothing: it does what a click anywhere else in the note does (in a link, what the link does). A one-line note's button sits after its text, a note of several lines has it at its top right as on a code block, and a `((…))` region has it right after the region (the maintainer, 2026-11-03: a click that copied was hidden behaviour, nothing on screen said so). The buttons are added in the page (`value-buttons-service.js`), so exports and prints keep their own click to copy.
- Text never runs out of its note, in MetaList, exports and prints: a word too long for the line (a token, a hash, a long URL) breaks at the note's edge, and code, `@json`, `@diff`, CSV and Markdown code blocks wrap their long lines, keeping spaces and indents, instead of scrolling sideways. The one exception is a table whose words can't all fit side by side: it scrolls sideways inside its note (only the table, never the note), because a table broken mid-word is unreadable.
- These are view-only: in edit mode you see just the raw value.

## Email meta tags
- `@email`: renders the note content as an email row in view mode: an envelope icon (hovering it says Email), then the address.
- Clicking the value opens the system email client (`mailto:`).

## Status meta tags
- `@todo`: renders the note content with an unchecked box icon in view mode; clicking the icon toggles the tag to `@done`.
- `@done`: renders the note content with a checked box icon in view mode; clicking the icon toggles the tag to `@todo`.

## Markdown meta tags
- **Standard Markdown always renders as standard Markdown** (the maintainer, 2026-10-31). MetaList follows CommonMark with GitHub's extensions (tables, task lists, footnotes): anything those define looks as they define it, in notes and in the AI chat's replies. Extras sit on top, only where the standard gives the text no other meaning: Obsidian's (callouts, `==highlights==`, `^[inline footnotes]`, `[[links]]` and `![[embeds]]`), LaTeX math, Mermaid diagrams, coloured code. Where Obsidian and the standard differ, the standard wins. A difference from the standard is a bug.
- `@markdown`: renders the note content as Markdown in view mode on the server.
- Scoped Markdown renders only the matching wrapped region.
- Any other scoped region in a Markdown note (`((@csv))`, `((@json))`, `((@diff))`, `((@code=…))`, `((@mermaid))`, `((@shell))`, `((@chess))`, `(((@LaTeX)))`) is drawn as in any other note. Its drawing is kept from the Markdown pass as a placeholder and put back after: an inline one (a formula, a chess board) in its paragraph; a block (a table, code, a diagram) as a paragraph of its own, so the text before and after it are paragraphs and a block never sits inside one (fixed 2026-10-29: only LaTeX survived, so a table showed as run-together text and a diff as a bullet list). Tests: `tests/unit/test_scoped_regions_in_markdown.py`.
- Paragraphs and line breaks (standard since 2026-10-31; before, every Return showed as a break, as in Obsidian): lines split by a single Return are one paragraph, joined by a space; a blank line starts a new paragraph. A line ending in two spaces or a backslash, or holding `<br>`, breaks there. A line without `>` right after a quote's text goes on with it, as one after a list item's text goes on with the item. Tests: `test_markdown_rendering.py`.
- Backslash escapes and underscores (standard since 2026-10-31, found importing an Obsidian vault): a backslash before ASCII punctuation shows that character as written (`snake\_case`, `1\. not a list`, `\*not emphasis\*`); a matched `\(…\)` or `\[…\]`, and anything inside a formula, stays LaTeX. An underscore inside a word never emphasizes (`snake_case_name`). A bare web address leaves a trailing full stop, comma, `?` or unmatched `)` out of its link, as GitHub does. Tests: `test_markdown_rendering.py`.
- Lists (standard since 2026-10-31): `-`, `+`, `*`, `1.` and `1)` start items (`3)` starts at 3); a change of bullet or delimiter starts a new list, and a list right after another stands 1em apart from it, so the two read as two. A line indented as far as an item's text (two spaces under `- `, three under `1. `, or a tab) belongs inside the item: a nested list, to any depth, bullets and numbers mixed, or, after a blank line, a paragraph, code block or quote of the item's own. A nested numbered list keeps its first number; an item indented less than its text stays a sibling. Two quotes split by a blank line are two quotes; a line holding only `>` keeps one quote. The AI chat's replies share this renderer. Tests: `tests/unit/test_markdown_rendering.py`.

## LaTeX meta tags
- `@LaTeX`: renders the note content as LaTeX on the server in view mode.
- The server emits final MathML directly, so normal app rendering and HTML export use the same rendered output.
- Invalid LaTeX shows a red "Invalid LaTeX" badge and the raw content.
- Inline math uses `$...$`; display math uses `$$...$$`.
- If no `$` delimiters are present, the entire note is rendered as display math.

## Previews while editing
Edit mode shows the raw text on purpose (precision, plain text that lasts, no hidden formatting); previews make raw formulas, tables, JSON and diagrams easier to edit without hiding them (agreed 2026-10-26; built 2026-10-29 in six slices, each tried by the maintainer before the next: LaTeX, CSV, Mermaid, then JSON, the preview card for the reference the caret is in (`docs/ui/references.md`, "The preview card"), the Insert helpers and the paste card's preview, below). Code has none: coloured, it looks as typed, and nothing checks it (checking a language's syntax would be a feature of its own). The rules every preview keeps: it shows only inside a region the note declares, with both delimiters there; it floats and never moves the note's text; it never changes the stored text; content that looks as typed gets none. LaTeX is drawn by the server, as the note is (`latex2mathml` has no browser version; a JavaScript renderer would draw differently), Mermaid by the browser, as the note is: each format keeps one renderer for the note and its preview.
- With the caret inside a formula of the note being edited, a small panel 6 px below the caret's line, its left edge at the caret, shows that formula drawn. A formula is any of the regions above: `$…$`, `$$…$$`, `\(…\)`, `\[…\]` in Markdown, a whole `@LaTeX` note or one of its `$` formulas, a `(((@LaTeX)))` region. Near the window's bottom the panel sits above the line. It follows the caret, moving once typing pauses (150 ms).
- With the caret in an `@csv` note or a `((@csv))` region, the panel shows that table exactly as the note draws it, at most 40% of the window tall (border included) and as wide as the window allows, scrolled so the caret's row is in its middle; nothing is highlighted. A table of one column (no row with two cells) shows nothing: it looks as typed. A caret just inside the region's `((` counts as inside, as for a formula's delimiters; a formula inside a table's cell shows the table.
- With the caret in a ```` ```mermaid ```` fence of a Markdown note, an `@mermaid` note or a `((@mermaid))` region, the panel shows the diagram drawn in the browser by the note's own Mermaid runtime, theme and layout (`mermaid-render-service.drawMermaidPreview`, in the same queue as the note's diagrams). The server finds the diagram as it finds formulas (`mermaid_note_rendering.finding_diagrams`) and sends its source. Nothing on the fence's ```` ``` ```` lines or in a fence without its closing ```` ``` ```` (still being written; the note draws such a fence to the note's end). It draws once typing pauses 400 ms. A diagram is never scaled up; one too big is scaled down, in proportion, to fit the panel (at most 40% of the window tall and as wide as the window): a tall one becomes small. Broken, it shows `Invalid Mermaid diagram` after the pause (Mermaid's own reason is not shown: reading it needs an exception boundary).
- With the caret in an `@json` note or a `((@json))` region, the panel shows the value laid out and coloured as the note draws it, and nothing when it is laid out so already (a preview would repeat it). Broken, it shows `Invalid JSON` with why and where, from Python's `json.tool` (`Invalid JSON: Expecting ',' delimiter: line 1 column 64 (char 63)`); JSON broken from the start shows only that, after the pause.
- Both delimiters must be there: outside a formula, on a delimiter, or with only the opening one, nothing shows. Nor for a formula that looks as typed (`$$x$$`, `$$12$$`): one shows only with a command, `^`, `_` or `{`.
- The server decides: the editor sends the note with a mark (the noncharacter U+FDD0) where the caret is, and `app/services/edit_previews.py` renders the note as it is shown, twice, listing its formulas, tables, JSON values and diagrams instead of drawing them (`latex_rendering.finding_formulas`, `content_formatting.finding_regions`, `mermaid_note_rendering.finding_diagrams`): without the mark and with it. The formula, table or JSON value holding the mark is drawn as the note draws it (`latex2mathml`; the CSV or JSON renderer with the region's own settings; `content_formatting.finding_regions` lists both) and sanitized (`sanitize_rendered_html`), but only when both renders met the same ones; when the mark changed what the renderer reads (inside a delimiter, after a `$` that opens nothing) there is no preview. So a preview never shows what the note would not. These renders fetch no link titles or icons (`content_formatting.holding_link_fetches`): a half-typed address is no site.
- Broken mid-typing, the last good drawing stays and fades to a ghost (opacity 0.25 over 600 ms); full strength again the moment it draws. After a 1.5 s pause a broken formula shows `Invalid LaTeX` (`latex2mathml` gives no further reason), a broken table `Invalid CSV` with why, as its badge's tooltip (`Invalid CSV: Row 31 has 5 columns, expected 4`); see above for diagrams and JSON. A command it does not know (`\fra`, half of `\frac`) is no error to it: the note shows its name as typed, so the preview fades while typing and after the pause shows it as the note will. The waits and the fade are constants at the top of `edit-preview-service.js`.
- The panel floats: no note moves when it appears, changes or goes. It takes the note's text size. Escape hides it without leaving editing, until the caret next enters a formula, table, value or diagram; scrolling hides it until the next key or caret move. Selecting text, as before typing over it, leaves it where and as it was (decided 2026-10-29: it had disappeared). `Previews While Editing` in the command palette (`pref.edit_previews`, on by default) turns previews off; the phone has none.
- The preview never changes the note: the mark goes into a copy of its text.
- **Insert ▸ LaTeX / CSV / Mermaid Diagram** (the editing menu, at the right-click; the command palette's Insert LaTeX, Insert CSV, Insert Mermaid Diagram, at the caret, outside edit mode in a new top note): declares the region and types its delimiters with the caret inside, so a preview shows as soon as something is typed. In an `@markdown` note LaTeX is `$$…$$` and a diagram a ```` ```mermaid ```` fence on lines of its own starting `flowchart LR`, the caret on its empty line; otherwise (and CSV always) the region is a wrapper no text or tag of the note uses yet, chosen as Add Style chooses one (`{@LaTeX}`, then `[`, `(`, deeper), its tag added to the tag bar, or the wrapper the tag bar already gives the format. Selected text goes inside the delimiters. A kind the whole note already is (`@LaTeX`, `@csv`, `@mermaid`) is not offered. The text goes in as typing: one ⌘Z takes it back (the tag stays, as with Add Style). `insert-format-plan.js` (what to type), `insert-format-service.js` (typing it).

## Shell meta tags
- `@shell`: renders the note content as a terminal-style script block in view mode.
- Scoped shell rendering applies only to the matching wrapped region.
- Shell execution requires a `--enable-shell` launch, a loopback client, and password protection on the active namespace. Otherwise, clicking the block shows an inline error and no process is started.
- In a password-protected namespace, clicking the block starts a background shell session on the connected server and streams stdout/stderr inline while it runs.
- Finished shell feedback stays inline until the user dismisses it with the `Close` button in the output header.
- The transport is cross-platform (Windows/macOS/Linux), but the script itself still runs inside the server host's shell, so command syntax must match that host environment.

## JSON meta tags
- `@json`: parses the note content as JSON and pretty-prints it in view mode.
- Scoped JSON rendering applies only to the matching wrapped region.
- Invalid JSON shows a red "Invalid JSON" badge and the raw content.

## CSV meta tags
- `@csv`: parses the note content as CSV and renders it as a table in view mode.
- Invalid CSV shows a red "Invalid CSV" badge and the raw content.
- Scoped wrappers (e.g. `((@csv))`) render only the wrapped region as a CSV table.
- Columns are at least as wide as their longest word, as in Markdown tables; a table too wide for its note scrolls sideways inside it.

## Chess meta tags
- `@chess`: reads the note content as a FEN (Forsyth–Edwards Notation) position and draws it as a chess board in view mode, White at the bottom, files a–h and ranks 1–8 labelled. Example: `rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1` is the starting position.
- Only the piece placement (the first field) is required. When the FEN has them, a caption under the board gives the side to move, the move number, castling rights and the en passant square.
- Pieces use the chess symbols of the system font, coloured white or black. Hovering a square shows its name and piece (for example "e4 white pawn").
- A FEN that does not parse shows a red "Invalid FEN" badge, what to fix, and the raw content.
- Scoped wrappers (e.g. `((@chess))`) draw a board for only the wrapped FEN, inside the surrounding text.
- One position per note or wrapper; whole games (PGN) are not supported.
- A hidden extra: typed in the tag bar, not offered in the Add Style menu.

## Diff meta tags
- `@diff`: shows the note content as a unified diff (what `git diff` and `diff -u` print) in view mode: added lines (`+`) green, removed lines (`-`) red, section starts (`@@ -1,3 +1,3 @@`) purple, file headers (`---`, `+++`, `diff --git`) grey and bold, unchanged lines plain.
- Lines jotted by hand with only `+`/`-` marks work too; nothing needs to parse, so there is no error state.
- Scoped wrappers (e.g. `((@diff))`) colour only the wrapped region.

## Code meta tags
- `@code=<language>`: shows the note content as source code with syntax highlighting in view mode, for example `@code=python`, `@code=javascript`, `@code=sql`. One tag for every language: any name or alias the server's highlighter (Pygments) knows works (`py`, `js`, `c++`, `c#`...), case-insensitively. The language name is shown above the code.
- An unknown language (`@code=pyhton`) shows the code plainly with an "Unknown language" badge.
- Scoped wrappers (e.g. `((@code=sql))`) highlight only the wrapped region.

## Stats of a subtree
Built 2026-10-27 (`app/services/subtree_stats.py`; design: `docs/design/tag-properties.md`, Later); empty figures and searching the figures built 2026-10-28.
- `@stats` shows, right under the note's own text and above its children, the numeric super tag values of the note and every note under it: for each property its Total, Min, Max and Count (the notes holding it).
- `@sum`, `@avg`, `@min`, `@max` and `@count` each show one figure: `@sum=calories` gives `Total calories: 1,605`; `@avg=` `Average calories`, `@min=` `Min`, `@max=` `Max`, `@count=` `Notes with calories`. Without a property (`@sum`) a tag covers every number property under the note. Several show in the order written; with `@stats` on the same note, a figure it already shows is left out (`@avg` is not one of them). The tag names are the spreadsheet functions; the labels are plain words.
- Each value counts once, on the note that writes it: the note's own values and its descendants', never inherited ones, and not those of notes it links to or embeds. Both `burger:calories=450` and a value on the tag itself, `calories=700`, count as `calories`.
- A note's values for a property are added up first, so Min and Max are the lightest and heaviest note (a meal), not its smallest ingredient; Average is over notes.
- Units are kept apart and never converted (`Total fat: 15g, 500mg`). Values that are not numbers (`snack:calories=lots`, dates, times) are left out, and a line under the figures says how many, once per property, for `@stats` and the single figures alike. Under `@stats` a property whose values are all text has only that line. A negative value lowers a total.
- **Nothing under the note yet** (a new day of a food log): `@sum` and `@count` show 0 (`Total calories: 0`), since the sum and the count of nothing are 0; `@avg`, `@min` and `@max` show a dash, since there is no such number. With only text values, `@sum` shows 0 and the line saying they are left out. A property no note in the vault has a value for shows a dash for every tag (`Total calroies: —`), so a typo shows. A plain `@sum` covers only the properties with numbers under the note, so with nothing under it, it shows nothing.
- **Searching the figures:** `@sum:calories>2000` finds the notes whose stats show a calorie total over 2000 (`docs/ui/search-semantics.md`, Stats Figures).
- Live: an edit to any note under it shows at once. Hidden while the note is folded, as footnote References are; shown in exports and prints too.
- **Stats Style** (command palette; `Strip` by default, `Tiles`, `Ledger`), each on a light accent tint so it reads as information about the note, not as an embedded note: a strip with an accent bar on its left, its figures on one line; tiles, a big number over its label; a ledger, dots leading from each label to its number. The page carries the choice as `data-stats-style`, and an HTML export or print carries it too.
- The tag bar keeps these tags; after `@sum=` (and the others) it suggests the property names used in the note and under it, the most used first.

## Mermaid meta tags
- `@mermaid`: the note content is one Mermaid diagram (no Markdown fence needed), drawn in view mode like a fenced `mermaid` block under `@markdown`, in its own block. Until it is drawn, and when it is invalid (with an `Invalid Mermaid diagram` badge), the source shows as a code block.
- Scoped wrappers (e.g. `((@mermaid))`) draw only the wrapped region.

## Paste format detection
- Pasting text in an unambiguous format tags the note for it at the moment of the paste (the tag appears in the tag bar; the text renders when the note leaves editing):
  - JSON (a complete object or array) → `@json`
  - a chess FEN position → `@chess`
  - a unified diff (with `@@` section lines, `---`/`+++` headers, or `diff --git`) → `@diff`
  - Mermaid starting with a diagram keyword (`graph TD`, `sequenceDiagram`, `gantt`...) → `@mermaid`
  - a fenced code block naming its language (```` ```python ````, ```` ```mermaid ````), alone or with text around it → `@markdown` (the fence says it is Markdown; a bare ```` ``` ```` or an unclosed fence is not enough)
  - a pure LaTeX block (`$$...$$`, `\[...\]`, or `\begin{...}...\end{...}`) → `@LaTeX`
  - code copied from VS Code (two lines or more) → `@code=<its language>`, from the language VS Code puts on the clipboard (`vscode-editor-data`): `@code=python`, `@code=bash` for shell scripts, `@markdown` for Markdown files; JSON that parses stays `@json`; plain text and unlisted languages get nothing
  - cells copied from a spreadsheet (Excel, Google Sheets, Numbers: an HTML table on the clipboard) → the cells as CSV text (commas, quoting cells that hold commas, quotes or line breaks) and `@csv`
- Into an otherwise empty note (or with all of its text selected), and when pasting creates a new note, the plain tag is added. Into a note with content, the pasted text is wrapped `((...))` and `((@json))` (etc.) is added, so the existing text is untouched.
- Nothing is added at once for anything uncertain (prose, JSON-looking text that does not parse); CSV-like, Markdown-like and code-like text is offered instead (see below). Nothing is added or offered when the note already has a renderer tag, when pasting inside an existing wrapped region, or when `((...))` is already in use in that note.
- `⌘Z` right after the paste removes the added tag together with the pasted text (one undo step, like a normal paste). `⇧⌘V` (Ctrl+Shift+V) pastes as plain text without detection.
- Implementation: `paste-format-detection-service.js` (detection and planning, tests in `tests/unit/paste_format_detection.test.mjs`), wired in `keyboard-events.js`.

## Paste format guesses
- Text that only looks like a format is pasted as plain text, and a small card just below where the paste ended offers it: `Apply as Markdown` (or `Apply as CSV`, `Apply as Python`) and `Skip`. When several languages are close, it reads `Looks like code:` with up to three, best first (`Ruby`, `Python`), then `Skip`. A wrong guess costs nothing.
- What is offered:
  - CSV-like: three or more lines with the same number of comma-separated cells (two or more; commas inside quotes do not count), short cells, no sentences → `@csv`.
  - Markdown-like: two or more different kinds of signs (`#` headings, a list of two or more items, `**bold**`, `` `code` ``, `[text](url)` links, `>` quotes), or two or more headings → `@markdown`. A table (`| a | b |` with its `---` line) or a bare fenced code block (```` ``` ````, opened and closed) settles it: such text is Markdown even when the code inside reads as HTML or Python. (A fence naming its language, ```` ```html ````, is tagged at once; see above.) A nested list is enough by itself (agreed 2026-10-31): an item two or more spaces (or a tab) deeper than the list item just above it, blank lines between allowed, as the Markdown view nests it. A lone flat bullet list or a single heading is an ordinary note and is not offered; nor is a list indented under a line that is not an item (`Shopping:` then `  - milk`, YAML's `key:` then `  - value`).
  - Code: mostly code-like lines (ending in `;`, `{`, `)`, `:`..., indented code, assignments and calls, no sentences), or a strong sign of one language → `@code=<language>`, for SQL, Python, Ruby, JavaScript, TypeScript, Shell (`@code=bash`), HTML, XML, CSS, Java, C, C++, C#, Go, Rust, YAML and Dockerfile, each scored on its own signs (`SELECT ... FROM`, `def f():`, `do |x|`, `console.log`, `#!/bin/bash`...). Notes of `key: value` lines are not YAML; a sentence mentioning "select ... from" is not SQL.
  - Markdown-like text with HTML tags in it, where HTML is the only code found, is offered as Markdown first and HTML second (2026-10-31): Markdown holds HTML (Markdown meta tags), so `<u>` or `<details>` among `**bold**` and `` `code` `` no longer makes it an HTML listing.
- A paste with formatting is checked too; see Formatted pastes below. Nothing is offered where nothing would be added (see above): Markdown into a note that is already `@markdown`, code into `@code=…`, CSV into `@csv`.
- The card moves nothing and never takes the keyboard: the caret stays where the paste ended. `Skip`, `Escape` (which closes only the card, not edit mode), typing on, a click elsewhere, scrolling the page yourself, or leaving edit mode closes it without applying; when MetaList scrolls on its own (a new note settling into view) the card stays with the paste. Near the bottom of the window it opens above the paste instead; the page never scrolls to show it.
- Pasting while no note is edited makes a new note at the top, as before; its paste is checked the same way (certain formats tagged at once, likely ones offered on the card once the new note is in place).
- The card shows the paste drawn in the format offered under its buttons, at most about 10 lines with a fade (2026-10-29; `POST /notes/format-preview`, `edit_previews.format_preview_html`); with several languages offered, pointing at one (or focusing it) shows the paste in that one. The card still floats and moves nothing.
- `Apply` adds the tag as a detected format is added: the plain tag into an otherwise empty note, or the paste wrapped `((...))` with `((@markdown))` into a note with other text. The note stays in edit mode and the text renders when it leaves editing. `⌘Z` right after removes the tag together with the paste, as for a format added at once.
- Implementation: `paste-format-guess-service.js` (the guesses; tests in `tests/unit/paste_format_guess.test.mjs`), `paste-format-offer-service.js` (the card; placement tests in `tests/unit/paste_format_offer.test.mjs`), wired in `keyboard-events.js` (`handleFormatGuessingPaste`, `applyGuessedFormat`); browser checks in `scripts/browser-paste-format-regressions.mjs` (`BROWSER_TEST_SUITE=paste-formats npm run test:browser`).

## Formatted pastes
- A paste whose clipboard carries formatting (bold, links, headings, code from a web page or an AI chat) goes in with its formatting, as always. Its text without the formatting is then checked as a plain paste is: Markdown left in it (`##` headings, `**`, fences, as Copilot answers often are), CSV, code, and the formats a plain paste is tagged with at once (JSON, LaTeX, a diff, Mermaid, a chess position). What is found is offered on the same card (`Apply as Markdown`, `Apply as LaTeX`), never applied at once, since applying drops the formatting.
- A fully rendered paste (real headings and bold, no Markdown signs left in its text) offers nothing. Formats the clipboard's plain text already settles (JSON, a fenced block naming its language, spreadsheet cells, VS Code code) are still tagged at once, as before.
- `Apply` replaces the formatted paste with its text and adds the tag, as for a plain paste: the clipboard's plain text when it reads as the same format (it often keeps the source, `**bold**` included), otherwise the text without formatting. `Skip`, or typing on, keeps the formatting.
- Implementation: `formatted-paste-format-service.js` (tests in `tests/unit/formatted_paste_format.test.mjs`), wired in `keyboard-events.js` (`planFormattedPasteOffer`).
