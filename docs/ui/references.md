# UUID References

## Status
- The written form decides, for notes as for files, anywhere in the text (Obsidian's convention; agreed 2026-10-26):
  - **Embed**: `![[UUID]]` shows the source in place. Alone in its note it is the note (the note holds it, below); amid other text it breaks the line and sits there as its own tinted block, the text before and after it on lines of their own. Characters with no width (a zero-width space, a byte-order mark) are not content.
  - **Link**: `[[UUID]]` is always a link, even alone in its note.
  - Before 2026-10-26 a note whose only content was `[[UUID]]` was an embed and `!` changed nothing. Nothing was migrated: those notes are links now, and an `!` makes one an embed again. Adding or removing `!` is an edit (it changes the note's updated time).
  - `[[` is the one way to make a reference: typed, or by Link to… and Embed… (Suggestions, below). Paste as Reference (⌘R, ⇧⌘R, the Paste submenu's reference items, Paste Note as Reference at Top) is gone; ⌘R does nothing, so a press from habit does not reload the page.
  - A link to an `@password` or `@username` note shows that note's own row: its icon and value (a password blurred), and clicking the value copies it with no stop at the note on the way; the link's reference icon still goes to the note (agreed 2026-10-26). Before, the link showed the password in plain text, as text that did nothing. Exports, prints and the AI show `••••••••`. An embed shows the note's row too. `tests/unit/test_password_reference_links.py`, `scripts/browser-credential-link-regressions.mjs` (Chrome and Firefox).
  - Typing `[[` in a note offers notes to reference (Suggestions, below).
  - **Link text** (agreed 2026-10-27, built 2026-10-27): `[[UUID|shown text]]` is a link that reads `shown text` instead of its target's first line, typed in the markup as Obsidian writes it.
    - The text is fixed: it stays as written when the target's first line changes. It is plain text: `<b>x</b>` reads as those characters. It runs from the first `|` to the `]]`, so `[[UUID|a|b]]` reads `a|b`; it can't hold `[`, `]` or a line break, and an empty or blank one (`[[UUID|]]`) is not a reference but text as typed.
    - It is a link like any `[[UUID]]`: alone in its note too, with the reference icon, the click, the Source note view and the preview card when the pointer rests on it (on its `|text` too, while editing). A link to a file reads the text in place of the file's name, after its kind badge; a link to an `@password` note reads the text, not the copyable row.
    - An embed's text is unused: `![[UUID|the plan]]` is the embed of UUID, as `![[UUID]]` is. The slot is kept for an image's size (`![[image.png|300]]`, `docs/future-plans/obsidian-import-export.md`).
    - Wherever a line is read as text, the link reads as its text: a link to a note whose first line holds one (`See [[UUID|the plan]]` reads "See the plan"), a folded note, an export's default title, the words the AI reads for an export title. Search already finds it (it searches a note's text). Every reference scanner takes the UUID before the first `|`: the parser (`parse_reference_inner`, `app/services/embedded_references.py`), backlinks, file names in search (`file_registry.py`), AI citations (`[[UUID|text]]` cites UUID; the text gives way to the citation marker), and in the browser the hover card and keeping a click after a reference in place on entering edit mode (`viewport-hold-service.js`).
    - `[[` suggestions write `[[UUID]]`; type `|text` before its `]]` by hand. Tests: `tests/unit/test_reference_link_text.py`, `test_ai_chat_rendering.py`; browser: `click-caret` (link-text clicks) and `reference-suggestions` (Chrome and Firefox).
  - Agreed, not started: Obsidian import and export, `![[Note]]`, `[[Note|alias]]` and `![[image.png|300]]` mapped both ways (`docs/future-plans/obsidian-import-export.md`).
- File references keep two forms: `![[UUID]]` shows the picture or diagram, `[[UUID]]` a file card.
- `[[...]]` containing exactly a note or file UUID is always a link, even when the note has a matching `[[...]]` scoped wrapper tag (for example `[[@LaTeX]]`); other `[[...]]` text is formatted by that wrapper, and links nested inside it still render.
- A UUID can resolve to:
  - a note
  - a file attachment

## Suggestions

Typing `[[` in the note being edited opens a list of notes to reference (agreed 2026-10-26); what is typed after it narrows the list. Choosing a note replaces `[[` and the typed text with `[[UUID]]`, as typing it would. `![[` works the same way and gives `![[UUID]]`, an embed.

- **Link to… and Embed…** (agreed 2026-10-26): while a note is edited, its right-click menu offers them first among the editing items, for a right-click in its text, and the command palette offers them too. Each types `[[` or `![[` where the right-click was (the palette: at the caret; outside edit mode, in a new note at the top, as Attach File does) and opens the list; text selected before the right-click follows the opener, so the list searches for it. They teach the syntax by typing it. Copy a note, add a note, type `![[`, press Enter: an embed of it.

- **The list** sits just below the `[[` (above it near the window's bottom), placed as the paste format card is, and stays put while the user types; it never moves the page. ↑/↓ move through it, Enter or Tab chooses the selected note, a click chooses one. Escape closes it and leaves the typed text, and that `[[` stays closed. Moving the caret away from the `[[`, a click elsewhere or leaving the note closes it. Enter on a list not yet updated for the last keystroke goes into the note as usual.
- **Nothing matching shows no list**; the typed `[[…` stays plain text. `[[@` starts a wrapper tag (`[[@LaTeX]]`), not a reference, and opens nothing. Text after `[[` longer than 80 characters or holding `[`, `]` or a line break opens nothing.
- **The copied note comes first** (agreed 2026-10-26): the note copied last (Copy Note, in any window of the vault) is first whenever it matches at all, from any tier, and first with nothing typed; when it doesn't match, it isn't shown. It stays first until another note is copied, with no time limit, and across restarts: the server keeps its id in the vault's client preferences (`pref.copied_note_id`, encrypted with a password, set only by Copy Note: a window saving its preferences keeps it). Copying an AI response, which is not a note, leaves it. A deleted note is not suggested.
- **What it finds**, in four tiers, strictly in order, at most 8 notes; within a tier, notes the tab's view shows come first (its search, filters and sort, as the view resolves them), then the most recently edited (`updated_at`). The view ranks, it never filters: notes outside it still appear, lower in their tier.
  1. the typed text in the note's first line (as its links show it);
  2. every typed word fuzzily in the first line: the start of a word there, or, for words of 4 or more letters, one edit away after the first letter (a typo, a swapped pair, a partial word with a typo: `bayse`, `factr`);
  3. the typed text in the note's text;
  4. every typed word fuzzily in the note's text.
  Matching ignores case and runs of spaces. Any note can be suggested, child notes too, but not the note being edited. With nothing typed yet, the list shows the most recently edited notes, the view's first.
- **Each suggestion** shows the note's first line; a note with no text of its own reads as a link to it does (one that is only a reference as its source, a password masked). A note with nothing to read (empty, or a picture alone) is not suggested. A match in the text (tiers 3 and 4) adds a grey snippet of about 40 characters on each side, with the match in bold. All of it is set as text, never as HTML.
- **Preview** (agreed 2026-10-26): the highlighted suggestion's card floats beside the list, level with the highlighted suggestion: on its right, or on its left where the window has no room; a window too narrow for either puts it under the list (over it near the window's bottom). Pointing at a suggestion highlights it as ↑/↓ do (only a pointer move counts, so a list drawn under a still pointer keeps its first suggestion).
- **The preview card** (agreed 2026-10-26) shows the top of the note as the list draws it: Markdown rendered for an `@markdown` note, headings and colours, checkboxes, links and embeds, pictures scaled to the card; an `@password` or `@username` note's value hidden (`••••••••`). It shows the note and its first descendants (at most 12 notes) at 14 px, cut at about six lines with a fade. It floats and takes no pointer: the note's text, the caret and the page never move. The same card shows for a **link the pointer rests on** for 0.3 s: in the note being edited, anywhere on its `[[UUID]]` or `![[UUID]]`, brackets included; elsewhere, on a link (an embed already shows its note). It sits just below that line from the reference's left edge, or just above the line near the window's bottom. Passing over without stopping shows nothing; moving off hides it at once; typing, a click, a scroll or the wheel hide it. A deleted note or a file's UUID shows no card; while the `[[` list is open only the list's card shows; touch shows none. Route: `GET /api2/notes/{id}/preview` (`note_fullscreen.build_note_preview_markup`, drawn in a shadow root with `main.css` and `reference-preview.css`, as floating windows are); browser: `reference-preview-card-service.js`, `reference-hover-preview-service.js`.
- **Credentials.** An `@password` note is never found or shown by what it holds: it follows its parent when the parent's first line matches (tiers 1 and 2), shown as the lock icon and `••••••••` with the parent's first line under it, and a link to it is the copyable row (above). An `@username` note shows the user icon and its value, and is found by its value (it is not hidden in the note either).
- **Speed.** The server keeps every note's first line and text, and the words in them by first letter, in a catalog (`app/services/reference_suggestions.py`) updated for the notes that changed since it was last asked (by the note store's revision). The first typing in a note after the page loads asks for it, so it is built (about 3 s for 100,000 notes) before `[[` is typed; then a keystroke takes at most about 115 ms on 100,000 notes (most under 30 ms), and the list waits 100 ms for typing to settle. A fuzzy search looks up the words that match, then the notes holding them, and every tier stops once the list is full. The catalog is a sensitive cache: locking empties it, and it shows in Memory Usage as Reference suggestions.
- Route: `POST /api2/notes/reference-suggestions` (`{query, editing_note_id, search, tabId, isUntaggedView}`). Editor: `app/static/js/modules/mode-manager/services/reference-suggestions-service.js`. Tests: `tests/unit/test_reference_suggestions.py`, `scripts/browser-reference-suggestion-regressions.mjs` (Chrome and Firefox).
- After choosing, type `|text` before the `]]` for link text (Status, "Link text").
- Agreed, not built (2026-10-27): the card also shows while the caret is inside a reference, and for a file's UUID, as part of smart previews (`docs/ready-to-build/smart-previews.md`, §4).

## Rendering Rules
- **View mode**:
  - Note targets:
    - **Embeds.** A note whose only content is an embed holds it: the note shows the source in place, tinted grey (light `#e4e7eb`; dark `#202224`), drawn exactly as the main tree draws notes: the same boxes, indent, spacing and ▾/▸ arrows. An embed inside an embed (a note in the source that is itself only an embed) is a shade deeper (`#d5dade`, then `#c6ccd2`; dark `#2a2d30`, `#35393d`). A holder folds when its source can (agreed 2026-10-26): it gets a ▾/▸ only when the source has more than its first line or has children (followed through a chain of holders), or when the holder has children of its own; an embed of a one-line note with no children has no arrow, even saved as folded, since folding would change nothing. The same holds inside embeds and in downloaded exports (`is_content_collapsible`).
    - **An embed amid other content** (agreed 2026-10-26) breaks its line and sits there as its own tinted, bordered block at full width; the text before and after it stays on lines of its own. It folds its source everywhere with its own ▾/▸ inside the block, on the baseline of the source's first line (as every fold arrow sits, `docs/ui/controls.md`); the note around it doesn't fold as its source (it is not a holder). A note folds to its first line as it is shown, and only the `!` decides whether a reference is an embed or a link, folded or not (agreed 2026-10-26): an embed of a note always starts a line of its own, so `Snack: ![[UUID]]` has two lines and a ▾/▸, and folds to `Snack:`; a note starting with an embed (`![[UUID]] for snack`) folds to that embed, still an embed, with its source folded. A folded note is one line (2026-10-27): every embed on it shows its source folded, cut with … when too long, and its own ▾/▸ is hidden (its space kept, so the line does not move) since the note's arrow unfolds it. `_first_shown_line` cuts the folded line at the first embed of a note. Nesting, the guard against a note embedding itself, hidden protected values, printing and HTML export work as for held embeds; a downloaded export shows it as MetaList does, without its own arrow. Clicking it edits the note around it, with the caret at the start of its `![[UUID]]`. A held embed's block has class `note-embed-held` (no panel, no arrow of its own); `app/services/embedded_references.py`.
    - The holder folds as its source: its ▾/▸ collapses or expands the source everywhere (the original in the tree and every other embed of it), and its own children with it. When the source is folded anywhere, the holder shows folded. Undo reverts both. Folded, the holder shows its embed, still an embed, with the source folded: the source's first line as a folded note shows it, on one line ending with … when too long, in its own formatting (a heading, a colour), a link on it as a link, a picture or diagram as itself; a footnote note keeps its markers and hides its references. A source that is only an embed is followed to the note it shows.
    - Each note inside an embed shows the collapse saved for it, with its own ▾/▸ where it can collapse, folded to one line as in the list; pressing it folds that note everywhere. A note being edited is saved and left first. Full screen and floating windows show no embed arrows.
    - The holder's own children (indented under it in the tree) show after the source's children, as notes of the level around the holder (white in the main tree). They belong to the holder, not the source: the source knows nothing of them, and they cannot be moved in among the source's children.
    - An embed's reference icon, a page with an arrow coming into it (tooltip: `Go to source note`), sits at its top right and opens the source note in a temporary reference-source context.
    - **Links.** A link is underlined link text, the referenced note's first line, followed by the same reference icon, in the line where it is written; no panel. A link to a note that is only a reference (an embed or a link) reads as that reference's source's first line. Clicking it opens the source in a temporary reference-source context.
    - when the referenced note's first visible line is an image or Excalidraw diagram, a link shows the same thumbnail the collapsed source shows (plus any text on that line) instead of `(empty note)`. AI chat citations stay text-only.
    - link previews retain first-line footnote superscripts, including markers attached from standalone footnote lines, without showing the reference bodies.
    - backlinks are off for now: no note shows the `↖` (Show backlinks) button, because an arrow pointing back reads as "back to where I came from", which it is not. A **Referenced by** view returns once backlinks have a visual of their own. Agreed, not built (2026-10-27): that visual is a count badge in link blue at the note's top right, opening Referenced by (`docs/ready-to-build/referenced-by-badge.md`).
    - Backlink membership and occurrence counts are cached in server memory alongside the note store. Hydration builds the index; content/accepted-tag changes, additions, deletions, and bulk-tag updates maintain affected entries. Collapse/expand and view refreshes reuse it without rescanning the namespace. Lock/reset clears it; restore/reload rebuilds it. Lists preserve current tree order and derive previews only for referring notes.
    - when a link's preview is a standalone URL with a cached link title, it displays the same `title · domain` treatment as the source note instead of the raw URL. Inline/prose URLs remain raw. Quoted-text search also matches cached titles of URLs in a note (`docs/ui/search-semantics.md`).
    - right-click anywhere inside a rendered reference and choose **Go to Source Note** to open that source note with the same navigation behavior.
    - An embed is a window onto its source: it can change how the source is shown (collapse), never what it says. Text, tags, to-do status and children are changed in the source (its reference icon). Clicking anywhere in an embed edits the note holding it (its `![[UUID]]` shows). A `@todo` / `@done` checkbox inside an embed shows the status but is not a control: pressing it does nothing (it neither toggles nor edits the holder; a note being edited stays edited).
  - File targets:
    - non-image files render a file card/link row with a deterministic type badge (`PDF`, `IMG`, `VID`, `TXT`, etc.) and the file title. `.txt`, `.md`/`.markdown`, `.csv` and `.json` files are labelled by extension (`.TXT`, `.MD`, `.CSV`, `.JSON`) whatever MIME type the browser sent; other files by their kind.
    - embedded image files (`![[UUID]]`) render an authenticated image preview with a `download image` control beneath it.
    - right-clicking the rendered image preview also offers image actions (`Copy Image`, `Save Image`, `Zoom Image`, `Open Image in New Tab`).
    - link-mode image files (`[[UUID]]`) keep the generic compact file card/link row.
    - embedded Excalidraw diagrams (`.excalidraw` files, badge `DRAW`) render their stored light or dark SVG preview; double-click or right-click **Edit Diagram** to open the full-screen editor. See `docs/ui/excalidraw.md`.
    - clicking the rendered file reference's badge (`.MD`) or its underlined name downloads the decrypted file from the server; hovering them shows the tooltip "Click to download <file name>". The rest of the note's line is the note: a click beside the name (also after a wrapped name's shorter last line) edits it and a drag there moves it, in the list, collapsed or expanded, and in floating windows. The button takes no clicks itself; the badge and an inline `.note-file-reference-name` around the name do (`main.css`). Tests: `scripts/browser-file-link-click-regressions.mjs`.
    - when the host note is collapsed, non-image file references stay visible as a single compact row showing the badge and a truncated title.
    - when the host note is collapsed and the first visible line is an embedded image file or diagram, the note collapses to a compact thumbnail-only version of that preview.
  - Rendered references have no embed/link controls: a reference is an embed or a link by its written form (`![[UUID]]` or `[[UUID]]`).
  - Opening a source (the reference icon or a link) opens a reference view (below); the internal UUID query stays hidden from the search input.
- **Edit mode**:
  - Note/file tokens remain literal raw text (`[[UUID]]`, or `![[UUID]]` for a file shown as its picture).
  - Saved-file image actions are not available from the raw token; they are available once the token renders as an image preview in view mode.

## File Attachment Workflow
- `Attach File…` in the command palette opens the native file picker.
- If you are editing a note, the selected file is uploaded and its `![[UUID]]` token is inserted into that note.
- If no note is active, the app creates a new note first, then inserts the file reference there.
- Drag/drop follows the same attachment path for non-image files.
  - Dropping onto the actively edited note inserts into that note.
  - Dropping anywhere else creates a new top note first, then inserts there.
- Dropped text files: a dropped `.txt`, `.md`/`.markdown`, `.csv` or `.json` file also gets its text as a new child note of the note holding its pill.
  - The child is the note's last child (after any existing children), in drop order when several files are dropped together.
  - Markdown children get `@markdown`, CSV children `@csv`, JSON children `@json`, text children no render tag; a child also gets the tags a new child gets from the current search.
  - The child starts expanded, so the dropped text is visible; collapse the pill note's children to hide it.
  - The child is an ordinary note: editing, moving or deleting it never changes the stored file, and the pill still downloads the original.
  - Files over 200 KB or not in UTF-8 keep only their pill; an info banner says why. Picking a file with `Attach File…` adds no child.
  - The text is stored line for line as escaped plain text (`<br>` between lines), never read as HTML.
  - Implementation: `app/services/file_text_preview.py`, `POST /api2/notes/file-preview-child/{note_id}` (`app/usecases/create_file_preview_child.py`), `dropped-file-preview-service.js`. Tests: `tests/unit/test_file_text_preview.py`, `BROWSER_TEST_SUITE=file-drop-previews npm run test:browser`.
- Named image files dropped or pasted into the editor prompt for one of two paths:
  - `Paste Inline`: embed the image into note HTML as compressed `data:image/...`.
  - `Save as File`: upload the original file without recompression and insert its `![[UUID]]` token.
- Pasting a named image while no note is active uses the same prompt and creates the destination note at the top.
- Clipboard image-pixel paste with no meaningful source filename keeps the direct inline embed path by default.
- The attach flow saves the note immediately after insertion so the new reference survives refresh/reload.
- `Add Excalidraw Diagram` attaches a new, empty `.excalidraw` file the same way and opens the diagram editor.
- Files live in a sibling SQLite database derived from the main DB path (`*.files.db`).
- Attachments are immutable except Excalidraw diagrams, which the diagram editor replaces in place under a per-file content revision (see `docs/ui/excalidraw.md`).
- Startup only loads the file UUID registry into memory; file metadata/blob rows are decrypted on demand for rendering/download.

## Failure / Safety Cases
- Missing or deleted UUID: render a "missing reference" marker (subtly red-tinted).
- Circular chain (A -> B -> A): render a "circular reference" marker and stop recursion at that point.
- Removing every note reference to a file does not delete the file automatically.
- `Trim Unused Files…` is the explicit cleanup path for unreferenced file rows (a reminder for it is agreed, not built: `docs/ready-to-build/trim-reminder.md`).

## Keyboard Workflow
- `Cmd/Ctrl + C` with no text selection copies a note (server clipboard + system clipboard payload).
- A reference to the copied note: type `[[` (or `![[` for an embed) and press Enter, since the copied note is the first suggestion. For a note that embeds it: add a note (Enter or +), type `![[`, press Enter.
- `Cmd/Ctrl + R` and `Shift + Cmd/Ctrl + R` do nothing (they pasted references until 2026-10-26); MetaList keeps them from the browser, whose `Cmd/Ctrl + R` would reload the page.
- Link to… and Embed… type where you right-clicked, or around the text you selected before right-clicking (a word the browser selects under the pointer does not count), with `reference-insert-point-service.js`. The note stays in edit mode; one `Cmd/Ctrl + Z` removes the opener.

- Deleting or cutting a note that other notes reference (link or embed, to it or to any note under it, from outside it) asks first: *"N other notes reference this note. Delete it anyway? Their references will show as missing."* (or *Cut*). A note being edited is saved and left before the dialog shows (interaction principle 6); Cancel leaves it in place, Delete or Cut goes ahead, and one undo brings it back with its references working. An unreferenced note is deleted or cut at once.

## Search Semantics
- Both embedded (`![[UUID]]`) and linked (`[[UUID]]`) note references contribute non-meta tags from the source and its complete descendant subtree, including further references within that subtree. Tags inherited from ancestors above the source are excluded. The host retains tags inherited from its own parents, and its children inherit the host's effective tags normally. Accepted and proposed tags remain separate until combined for search.
- Required and excluded tag searches, tag suggestions, inherited-tag metadata, and Untagged Notes use these effective tags. Example: a source tagged `foo`, a reference to it, and a child beneath that reference all match `foo` and are excluded by `-foo`.
- For `foo → bar → baz`, referencing `bar` matches tags on `bar` and `baz`, without inheriting tags from `foo`. Searching for a tag on `baz` shows the reference host, and an expanded embed displays `bar → baz`. Canonical notes retain ordinary ancestor-tag inheritance; link-mode references retain compact rendering.
- References do not import source text for quoted-text searches, meta tags, or tag-bar comments. Ontology implications and text matchers still run per note after inheritance.
- Reference chains propagate transitively within each referenced subtree boundary. Cycles are valid; removing tags or references recomputes the affected dependency closure from direct tags so cycles cannot retain stale tags. Explicit references to ancestors contribute their subtrees normally. Missing/file targets, self-references, and formatting scopes do not supply note tags.
- Hydration caches effective tags in the note store/search index. Edits, bulk tag changes, moves, deletion, and restoration update the affected references and descendants; collapse and view refreshes reuse the cached tags.
- Reference views (`reference-source-navigation-service.js`, `reference-view-transition-service.js`):
  - Following a reference (a link, an embed's reference icon, Go to Source Note, a floating window's title), or an AI answer's references, opens a temporary tab that searches for the referenced note IDs internally. The search input fades out and a gray chip grows in (about 200 ms), centered in the black bar: `Source note` (the source's first line is its tooltip), `Reference` (one AI citation) or `All references` (an AI answer's Open all references), each starting with its icon (the reference icon; two pages for All references). The tab list shows the same label and icon. A magnifier stays where the input began.
  - The list of notes slides as one piece (a transform, about 250 ms): the old view out to the left and the new one in from the right; coming back slides the other way. With the system's Reduce Motion on it is a quick fade (120 ms); with Animated Transitions off, and on a page nobody sees, nothing moves. Nothing waits for the slide: the navigation is done when the new view has rendered, and the slide cleans up after itself. Where the new view lands is unchanged; reloads, tab switches and opening a tab already in a reference view never animate.
  - Following again from a reference view slides left once more; the chip shows the new view and gains a `←` (tooltip `Back`). `←`, or Escape outside editing and dialogs, goes back one level; `×` (tooltip `Back to your search`) goes straight back to the search the views started from, from any depth, closing every reference tab on the way. Both return to the exact scroll position the user left.
  - A later AI reference while AI references are shown replaces that view (sliding in from the right, no new level); the same references clicked again while shown do nothing.
  - The magnifier brings the empty search input back, focused (saving and leaving a note being edited first); typing starts a new search and turns the reference tab into an ordinary search, as before. Leaving the empty input without typing brings the chip back.
  - Which tabs are reference views, and the tab each was opened from, is kept with the tabs on the server (tab state `referenceViews`, inside its encrypted record), so a reload, another window or another device shows the same chips and tab labels. A view ends when its tab runs another search or the tab it came from closes. A tab whose search is only note IDs but that no view claims (its origin closed, or an older window kept it only in its own `sessionStorage`, which moves to the server once) becomes a view opened from the tab before it, so no tab is named by a note ID; its `×` closes it and goes there.
  - Temporary reference mode is registered before activating the tab, so even nested reference navigation never briefly exposes an inherited UUID query in the search field. Deleting an inactive temporary tab preserves the restored context's rendered root window and infinite-scroll tracking.
  - Opening, replacing, or returning from reference views applies note changes immediately, without note appearance/disappearance or collapse animations.
  - Tests: `scripts/browser-reference-view-regressions.mjs` (`BROWSER_TEST_SUITE=reference-views`).
  - Target note is included.
  - Target ancestors are included.
  - Target descendants are included (not redacted).
  - Non-matching sibling branches in visible context are redacted via normal search rules.
