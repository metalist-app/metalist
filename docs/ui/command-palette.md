# Command Palette

Open with `⌘ + /` or the menu (`≡`) button in the upper right.

## Undo/Redo Boundary
Opening or dismissing the command palette does not clear undo/redo. Global actions establish their own boundaries; bulk tag proposal actions clear the existing stacks only after successful changes and create no undo entry. Failure, cancellation, or no changes preserves history. See [undo/redo scope](state-handling.md#bulk-operations-are-outside-ordinary-undoredo).

## Tag proposal controls

- **Accept or Reject AI-Proposed Tags…** (tags the AI chat proposed, not yet accepted) selects acceptance/removal, current context/entire namespace, and an exact case-insensitive tag filter (blank means all proposals). Apply executes directly without another confirmation, model call, or progress/cancellation modal; the normal busy spinner remains visible until completion. How many proposals changed shows as a corner card and the dialog stays open; a refused Apply opens the error dialog over it.
- **Reject All AI-Proposed Tags (Current Context)…** asks for confirmation, then removes every pending proposal in the active search context. It uses the same atomic bulk path and requires no configuration form or model call. After confirmation, the normal busy spinner replaces the confirmation without opening a second modal.
- **AI Tagging Vocabulary…** sets one categorical preference: existing tags only or allow new tags. The tagging instructions are packaged and not editable.
- Generate proposals by explicitly requesting them in AI chat. Generation is not a menu action.

## Semantics
- Query is an unordered bag of words.
- While the palette is open its order holds: rows and suggested keywords are ranked by how often each command was used as of opening, so using one (cycling `Theme` or `Stats Style`, say) never moves the row under you. The uses count from the next opening (agreed 2026-10-27; `browser-palette-order-regressions.mjs`).
- AND-only matching against each command's keywords (`app/static/config/command_palette_tags.json`). The palette calls them keywords, never tags, so they aren't mistaken for note tags: the input reads `Type keywords to find a command…`, and the words suggested under it are plain text.
- While you are mid-token (no trailing space), it behaves as a prefix filter.

## Results
- Labels are in Title Case. A trailing `…` means the command opens a dialog that asks for
  more before anything happens; commands that act at once or only show something have none
  (`endpoint-registry.js`; the conventions: `docs/ui/modals.md` ("Dialog and menu conventions")).
- A command with a key of its own shows it at the right (`Find in List` ⌘F, `Keyboard Shortcuts` ?).
- Destructive commands (they lose what cannot be brought back: `Delete Vault…`, `Remove Password…`,
  `Restore from Backup…`, `Trim Unused Files…`, `Reset All Preferences`, the reorderings and the
  repair) are red; they keep their place, since results are ordered by use and search.
- Commands that cannot apply are left out: `Add Password…` once the vault has a password,
  `Change Password…` and `Remove Password…` until it has one, and the root-note reorderings
  (`Prioritize…`, `Alphabetize…`) in a sorted search context.
- Booleans toggle with `Enter`.
- Boolean labels describe the next action: `Show …` while hidden and `Hide …` while visible.
- Selects cycle with `Enter` (and adjust with `←`/`→`).
- Actions run with `Enter`.

## Sort Order
- The notes-view background and side-rail right-click menus also offer **Sort by**: Normal, Datetime Created, Datetime Last Updated, Alphabetical, and Content volume (largest first). The current mode is labeled and disabled. Choosing a mode updates the same saved per-search-context setting as the command palette; Normal restores manual order.
- `Sort order` is a per-search-context, server-owned view setting. Duplicating a search context inherits its current sort mode.
- Modes are exposed as distinct actions: `Sort Order: Normal`, `Sort Order: Datetime Created`, `Sort Order: Datetime Last Updated`, `Sort Order: Alphabetical`, and `Sort Order: Content Volume (largest first)`.
- Datetime Created orders roots newest-first by each root note's own creation timestamp; children do not affect its position or date group.
- Datetime Last Updated orders roots newest-first by the latest update timestamp anywhere in the root's subtree, including the root and all descendants. Date groups use that same timestamp.
- Changing a reference between link and embedded form preserves the host note's update time, including undo/redo and manually changing only that marker. Adding/removing references, changing their targets, or editing surrounding content still advances the timestamp.
- In alphabetical mode, root notes are ordered by root-note content without rewriting the stored manual order.
- In content-volume mode, roots are ordered largest-first by the total plain-text character count of every note in each root subtree. HTML markup does not count, and equal totals preserve manual root order. Search phrases include `character count`, `content volume`, `length`, and `longest`.
- The server returns the ordered root window plus `sortMode`/`rootSortBuckets`; the client inserts day-separator rows between visible roots.
- Sorted search contexts limit new root notes and freeze the order while a note is edited; the full rules are in `docs/ui/controls.md` (Sorted search contexts: adding and editing notes).
- **Reverse Order** (a check item under the orders in the Sort by menu; `Sort Order: Reverse` in the palette) combines with any order, Normal included: Z to A, the date orders oldest first, Content volume smallest first, the manual order bottom to top. Date separators flip with the notes. Picking another order keeps it. Saved as the order's name with `-reversed` (`alphabetical-reversed`); an older MetaList reads that as Normal. While reversed, root notes cannot be moved and no new root notes can be added.
- When a non-normal sort mode is active, a gray chip at the right end inside the search input names it: `Created`, `Updated`, `A–Z`, `Size`; reversed `Created ↑`, `Updated ↑`, `Z–A`, `Size ↑`, or `Reversed` for Normal reversed. Its full name is the tooltip; its `×` returns to Normal (not reversed). The typed search stops before the chips. A chip grows in or shrinks out only when the user changes the order in that search context, never on a reload or search-context switch.
- Changing sort mode is treated as a global view-context switch: the search context's scroll state resets and undo/redo history is blanked for that context.
- Changing the search input resets the active search context's sort mode to Normal before executing the search. Leaving a search context (picking another, or opening a new or duplicated one) does the same for the context left, and a new blank search context starts in Normal order. Following a reference and coming back keeps the sort.

## Date Range
- **Date Range** (after Sort by in the background, side-rail and search-box right-click menus; `Date range: …` in the palette) shows only the root notes whose date is in a range, each with its children. First the date, ticked: **Last Updated** (the latest update anywhere in the root's subtree, as the Updated sort uses) or **Created** (the root's own creation, as the Created sort uses, or the date of the root's own `@datetime` tag: `docs/ui/tag-bar.md`, Date meta tag). Then the range: **Any Date** (no filter), **Today**, **Last 7 Days**, **Last 30 Days**, **This Year** (each counted back from today, today included, so it moves with the calendar), and **Custom Range…**, a dialog with Last updated/Created and From and To dates (local days, both included; either may be left empty: `since Oct 1`, `until Oct 23`). Apply stays dimmed until there is a date and From is not after To. Picking the other date moves the active range to it; with no range it is used for the next one.
- It combines with a search, Untagged notes and any sort order: a search or Untagged view shows only matches under the roots the range keeps.
- A chip inside the search input, after Untagged and before the sort chip, names it: `Updated · today`, `Created · last 7 days`, `Created · Oct 1–22`, `Updated · since Oct 1`; the full wording is its tooltip and its `×` shows every date again.
- It is a per-search-context, server-owned setting (tab state `dateFilters`, `POST /notes/tab-state/date-filter`; `app/services/root_date_filter.py`, `date-range-filter-service.js`). Like a sort order it ends with its `×`, a new search, or leaving the search context (picking another or opening a new one); a new or duplicated search context starts without one, so a reference view always shows its source. Following a reference and coming back keeps it. Changing it resets the search context's scroll and undo/redo context.

## Notes With Files
- **Notes with Files** (after Date range in the background, side-rail and search-box right-click menus; `Notes with files: …` in the palette) shows only the notes with an attached file, or a file of one kind, each with the notes above it: **All Notes** (no filter), then **Any File**, **Images**, **PDFs**, **Markdown Files**, the current one ticked. A note counts by its own text: a `[[file]]` link or `![[file]]` embed in it (not a file in a child, or in a note it embeds). **Images** also finds a picture pasted into a note's text, which is not an attached file. A file's kind comes from what MetaList already knows of it: images and PDFs from their type, Markdown files from a `.md` or `.markdown` name.
- It combines with a search (only the matches with such a file), Untagged notes, a date range and any sort order. Unlike a sort order or date range, a new search keeps it: picking Images and then typing `beach` finds the beach notes with a picture. It stays with its search context when you leave it and come back; a new or duplicated search context starts without one.
- The note being edited stays while it is edited, also once its file is taken out; it leaves the view when editing ends.
- A chip inside the search input, after the date range, names it (`With files`, `With images`, `With PDFs`, `With Markdown files`; the tooltip says `Notes with an image`, etc.); its `×` shows every note again.
- It is a per-search-context, server-owned setting (tab state `fileFilters`, `POST /notes/tab-state/file-filter`; `app/services/file_kinds.py`, `file-filter-service.js`). The notes come from the backlink index (the notes referencing each file of the kind, and the notes with an inline `<img>`, both kept as the notes change), so the filter reads no note text. Changing it resets the search context's scroll and undo/redo context.
- While a note is edited it stays in view even when saving (or adding it today) puts its date outside the range; after leaving edit mode it leaves the view.
- Export, Print, find, robot counts, AI tag suggestions and the AI chat's view scope all use the search context's range. Moving to the top, Alphabetize and Reset Updated keep acting on the whole search.
- Tests: `tests/unit/test_root_date_filter.py`, `checkDateRange` in `scripts/browser-search-input-regressions.mjs`.

## Untagged Notes View
- `View: Untagged Notes` temporarily overrides the displayed results with notes that have no non-meta effective tags while preserving the active search context and its search. Its search box is visually blank because the preserved query is not active.
- `View: All Notes` returns to the search context's underlying view. The active untagged view also appears as an `Untagged` chip inside the search input, before any sort chip.
- The setting is transient and independent of the search context: it is not persisted or inherited when a search context is duplicated.
- Clicking any search context, changing the search input, or dismissing the chip exits the untagged view. The chip's × works with one click while a note is being edited (the note is saved and closed as the view changes); like the other view chips, pressing it does not end the edit on its own (`tests/unit/view_indicator_edit_exit.test.mjs`). Changing it resets the active display's scroll state and undo/redo context.

## Config
- Tag mappings live in `app/static/config/command_palette_tags.json`.
- Keyword policy for a new or renamed command: every word of its label (two letters or more) finds it on its own, added when the palette loads (`withLabelWords` in `tag-config-loader.js`; tests: `tests/unit/command_palette_tag_config.test.mjs`), so `edit` finds `Edit Tag Relationships…`. The config lists only the other words someone would type for it: the topic (`ontology`), synonyms (`imply`, `graph`), and what it is about when the label does not say. Never remove a configured keyword because the label lacks it, and never repeat label words in the config. Every command needs at least one configured keyword (the loader requires the row).
- Search `LLM` or `OpenAI` to find `AI Agent Settings` for API key and model configuration.
- Endpoint definitions (behavior/labels) live in code.
- Palette preferences (`pref.*`) and command usage history are persisted per namespace in the main SQLite DB via `/api2/auth/client-state*`, not in browser `localStorage`.
- `Stats Style`: `Strip` (the default), `Tiles` or `Ledger`, how `@stats` and `@sum=…` look (`docs/ui/content-formatting.md`, Stats of a subtree); Enter cycles it like `Theme`. Saved per namespace; an HTML export or print shows the stats in it too.
- `Animated transitions` is on by default and controls UI motion such as tag-bar edit transitions, note expand/collapse transitions, the login screen fading out over the notes, and the page cross-fading (300 ms) when `Theme` changes.
- `Note Layout & Appearance…` stores namespace-scoped presets for top-level note size, child indentation, vertical spacing, note corners, and tag style. The defaults are `Larger`, `Standard`, `Comfortable`, `Round`, and `Pills` respectively. Note corners can be `Subtle`, `Rounded`, or `Round`; tag style shows visible note tags as outlined `Pills` or `Plain text` in both themes.
- `Search Suggestion Stats & Settings…` is the single suggestion-personalization control surface. Its ordered 1–365 day slots and default-on time-window-label and one-credit-per-note-per-search-context toggles save immediately when changed. The modal also displays retained daily tag-credit statistics and provides the confirmed activity reset. An empty slot list disables personalization; the default slots are 1, 7, and 30 days.
- `Show/Hide AI Chat` controls the resizable right-side chat panel.
- `AI Chat: Summarize Now` replaces every turn the AI still sees with a summary the user can read (`docs/ui/ai-chat.md`, Long chats); with nothing new since the last summary it says "Nothing to summarize yet".
- `AI Agent Settings`: configures the OpenAI API key, model, cloud privacy policy, evidence-token limit, and tagging batch size. Model and thinking level are also selected beside chat Send. See `docs/ui/ai-chat.md`.
- Session Idle Timeout… is disabled by default. It is a namespace-scoped server setting stored in `app_settings` and managed via `/api2/auth/settings/session-timeout`. Expiry requires browser reauthentication but preserves the hydrated server cache for a fast login; explicit logout still purges decrypted runtime state.
- On first launch after this change, the browser imports any legacy command-palette `localStorage` values into the namespace DB and then clears those legacy keys.

## Utility Actions
- `Back Up Now…`: opens Backup Settings, where the user chooses one backup folder, picks which vaults to include, and sets the retention count. The vault choice is remembered per vault: the dialog opens with the vaults checked as they were at the last backup, a vault created since then starts checked (an unchecked new vault would never be backed up, with nothing to warn of it), and the vault in use is always checked, its box locked (drawn checked like the others, not grey, with a tooltip) and the server refusing a run without it. The settings keep the vaults left out, not the ones checked; settings saved before 2026-10-29 are converted once after unlock (`backup_settings_service.convert_backup_settings_to_unchecked`, recorded in `namespace_content_migrations`). `Back Up Now` submits those settings directly to the backend operation that persists them and creates the archives; the completion modal appears only after concrete archive results return and shows the created size per namespace. Typing `backups` in the palette also matches this action. A synced folder is the way to keep backups off the computer (built 2026-10-29): MetaList holds no cloud credentials, the provider's app uploads what lands in the folder. **Suggested folders** above the folder path: `Downloads` first, then `Dropbox › MetaList Backups`, `Google Drive › My Drive › MetaList Backups`, `OneDrive › MetaList Backups`, `iCloud Drive › MetaList Backups` for each synced folder found, each only if it exists; the one holding the chosen path is outlined and bold, and clicking it again changes nothing. They are found by name only, never by reading their contents: on macOS the entries of `~/Library/CloudStorage` and iCloud Drive's folder, on every system `Dropbox`, `OneDrive…`, `Google Drive` and `iCloudDrive` in the home folder (`app/services/synced_folders.py`). Not found yet: Google Drive mounted as its own drive letter on Windows. **Before a vault without a password is backed up into a synced folder**, a confirmation asks: `This folder syncs to Dropbox, and "Recipes" has no password, so its notes will be readable there. Set a vault password, or back up anyway.` with `Back Up Anyway`; it asks once per folder and vault (remembered in the backup settings, `synced_plaintext_acknowledged`), and the server refuses a run that skips it (`POST /api2/backup/plaintext-check`, `409` from `/backup/run`). Saving a folder (as the restore dialog's folder chooser does) asks nothing, since it writes nothing there. **A backup never sits half-written under its name:** it is written to `<name>.partial`, fsynced, then hard-linked to its name, which fails if the name exists; a crash leaves only the `.partial`, which Restore and pruning never match and the next backup of that vault removes (`docs/security/README.md`, "Backup Immutability"). Tests: `tests/unit/test_synced_folder_backups.py`, `tests/unit/test_backup_partial_archives.py`. Later, MetaList uploading to S3-compatible storage itself (`docs/future-plans/backups-s3.md`).
  - Each backup snapshot is one versioned `.tar.gz` archive containing the notes DB plus sibling files DB when present.
  - The completion modal shows one result row per namespace.
- `Backup Reminder`: `Off`, `Daily`, `Weekly` (the default), `Every 2 weeks` or `Monthly`, saved per namespace; Enter cycles it like `Theme`. When this namespace's newest backup in the backup folder is older than that (or there is none), a card floats at the bottom right: `Time to back up: the last backup was 9 days ago.` with `Back Up Now` (opens Backup Settings, as `Back Up Now…` does) and `×` (hides it for a day). It is not a Reminders reminder. It takes no space and never takes focus; it waits while a dialog or the menu is open, stays until a backup succeeds (cancelling Backup Settings keeps it), and goes away when set to `Off`. It is checked when MetaList opens, when its tab comes back, when a dialog or the menu closes, and on the first click or key after a while.
- `Restore from Backup…`: opens a restore picker for configured-folder snapshots, applies the selected archive, then shows a success confirmation with `OK` before reload.
  - Restore reuses the same archive pipeline for both sources and recreates the sibling files DB from the archive contents. The source archive and legacy sidecars remain byte-for-byte unchanged; legacy search-history sidecars are ignored.
- `Export View as HTML…`: downloads a self-contained HTML file of the current view as shown (its search, sort order, Untagged view; notes the search leaves out are absent, not grey bars) with inline CSS, the active light/dark theme, notes starting collapsed and expanded as MetaList shows them (embeds too; the note being edited open), no command/search chrome, MetaList's collapse arrows (one collapses its note to the first line and hides its children), and click-to-copy for usernames, included passwords and `@copyable` values. A dialog comes first: the title (default selected: the note's first line, `MetaList`, `MetaList — <search>` or `MetaList — Untagged notes`; it heads the file and names it, `Spring in Kyoto.html`), `🤖 Suggest with AI` with an AI set up (only pressing it asks; it never sees private notes, passwords or the search), and, if it shows `@password` or `@username` notes, an `Include Unredacted Passwords` / `Usernames` / `Usernames and Passwords` checkbox (unchecked: each shows `••••••••`; checked: plain and readable). The title heads the file unless the first note already says it.
- `Print View…`: prints the current view as shown through the browser's print dialog (Save as PDF included): always light, fully expanded, no arrows. The same dialog comes first (title, `🤖 Suggest with AI`, Include passwords); Enter prints, Escape cancels. It uses the page's full width with its own margins, so the browser prints no header or footer. The title heads the first page and names the PDF.
- `Log Out`: revokes the current session and returns to login.
- `Generate Random Password…`: opens a password generator modal: `Made of` Characters (length and character set) or Words (a word count, 5 by default, up to 7, from the passphrase wordlist: `docs/security/README.md`, "Password Requirements"), explicit `Copy` and `Regenerate` actions, the standard modal `×`, and a clipboard handoff that auto-adds `@password` when that copied value is pasted into an empty note. Its help lives in tooltips (the character set, the candidate field, Copy, which reads `Copied` after copying) so the dialog fits without scrolling.
- Password alphabets ignore line breaks and duplicate characters; each distinct Unicode code point has equal selection probability. Length counts Unicode code points, so an ordinary emoji counts as one; combined emoji sequences may contain several code points.
- `Session Idle Timeout…`: opens a modal for changing the namespace-scoped inactivity window before reauthentication is required again, or disabling idle timeout entirely.
- `Open Reminders`: opens the privacy-first in-app reminder registry and builder. Reminders are namespace-local, encrypted with the namespace when password protection is enabled, and never use browser/system push notifications. See `docs/ui/reminders.md`.
- `Keyboard Shortcuts`: opens the keyboard shortcuts cheatsheet from the command palette; `cheatsheet` is a searchable keyword.
- `Version Info`: opens a read-only runtime/version modal with app version, SQLite `user_version`, namespace, auth, encryption, vault, KDF, and cache readiness fields.
- `Note Layout & Appearance…`: previews and saves the note hierarchy presets. Search terms include `layout`, `appearance`, `font`, `size`, `spacing`, `indentation`, and `hierarchy`.
- `Search Suggestion Stats & Settings…`: combines ordered personalized-window editing, promoted-suggestion label visibility, default-on per-context note-credit suppression, retained daily tag-credit statistics, and confirmed activity reset. It does not collect search text or note content.

Deletion never requires the namespace password, so an inaccessible encrypted namespace can still be removed. Deleting the active namespace moves the tab to a dedicated namespace-removal status page; deleting an inactive namespace stays in the current tab and reports completion in the modal.
- `Attach File…`: opens the native file picker, uploads the selected file, and inserts an embedded file reference token into the current note. If no note is active, it creates a new note first.
- `Link to…` / `Embed…`: type `[[` or `![[` at the caret of the note being edited (or in a new note at the top when none is, unless the search context's sort order keeps new notes off the top) and open the note suggestions, the note copied last first. See `docs/ui/references.md`.
- `Add Excalidraw Diagram`: attaches a new, empty Excalidraw diagram to the current note (or a new note when none is active) and opens the full-screen diagram editor. See `docs/ui/excalidraw.md`.
- `Trim Unused Files…`: deletes file rows whose UUIDs are no longer referenced anywhere in note content. It is the only cleanup for files no note uses, and a manual one: nothing deletes them automatically. A file is unused when no live note's text references it (read from the note store's reference index, `NoteStore.referenced_target_ids`) and no search context's undo or redo history or copied note names it: Trim never deletes a file that ⌘Z or a paste could bring back (built 2026-10-29; before, undoing a note delete or pasting a copied note after a trim pointed at a deleted file). The confirmation says what goes: `Delete 4 unused files (12.0 MB)? This cannot be undone.`, or `No unused files to trim.` when there are none. Implementation: `app/services/unused_files.py` (`GET /api2/files/unused` totals them; `POST /api2/files/trim-unused` deletes them); tests: `tests/unit/test_trim_keeps_undo_and_paste_files.py`.
- `Trim Reminder`: `On` (the default) or `Off`, saved per vault. Once files no note uses (as Trim counts them) add up to 10 MB, a card floats beside the backup reminder, styled like it: `12.0 MB of files aren't used by any note.` with `Trim Unused Files…` (the usual confirmation) and `×`. It only asks; nothing is deleted automatically. After `×` the card comes back only once another 10 MB has piled up (`pref.trim_reminder_dismissed_bytes`, lowered when unused files shrink below it). It is checked when the backup reminder is, never by polling, and goes away after a trim or when set to `Off`. Every backup is the whole archive, so unused files ride along in each until trimmed. Implementation: `trim-reminder-service.js`, `trim-reminder-schedule.js`; tests: `tests/unit/trim_reminder_schedule.test.mjs`.
- `Retry Failed Link Titles…`: asks every web link whose title lookup failed (rate limited, refused, login or verification page, no title, timed out, page not found and other errors) again now. It opens a dialog saying how many links it would ask; nothing runs until its **Retry N links** button (or Enter). Unsupported links (such as PDFs) and private-network links are not retried. It uses the usual polite pacing: one request per site at a time, 2 seconds apart; a site that answers "too many requests" is skipped for the rest of the run and its links keep their normal retry schedule. The same dialog then shows progress: links asked, titles found, what still fails and why, and skipped sites. It does not block the app: closing the dialog (×, Escape or a click outside) leaves the retry running, and running the action again shows its progress instead of starting another. **Stop** drops the lookups not yet started; logging out, locking or logging in also stops it. Titles found appear in notes at the next view refresh.
- `Prioritize Tag to Front (Global)…`: opens a warning modal with single-tag input and suggestions from all root notes. Applying it stably moves all matching root notes to the front of the global root order while preserving relative order inside the matching and non-matching groups. Cmd+Z cannot undo this action; the undo/redo queue is cleared.
- `Prioritize Tag to Back (Global)…`: same as above, but stably moves all matching root notes to the back of the global root order.
- `Alphabetize Root Notes A-Z (Current View)…`: after confirmation, permanently rearranges only root-level notes in the active search context by root-note content. Hidden roots and child notes are not reordered. Cmd+Z cannot undo this action; the undo/redo queue is cleared like a view-context switch.
- `Alphabetize Root Notes Z-A (Current View)…`: same as A-Z, but descending by root-note content.
- `Repair: Reset Updated Time to Created Time (Current View)…`: after confirmation, resets every note inside each matching root subtree in the active search context so `updated_at = created_at`. Notes outside the current view are not changed. Cmd+Z cannot undo this action; the undo/redo queue is cleared.

## Collapse/Expand All
"(current view)" means the full active search context (not just rendered DOM).
The implementation uses `POST /api2/notes/set-collapsed-in-context`.

- **Expand all root notes** and **Collapse all root notes** update only the roots in that context. Child and deeper descendant notes retain their saved states.
- **Fully expand all notes** and **Fully collapse all notes** recursively update every descendant under those roots, including descendants that are not currently rendered because an ancestor is collapsed.

These are treated as **global** actions:
- The client bumps the undo-context epoch.
- The server clears undo/redo history for the active undo context.

## Opening menus through chat

The agent can select a documented dialog or command-palette destination. Dialog
entries reuse the existing form opener; operation/toggle entries are highlighted
without executing. The shared allowlist is `app/static/config/agent-menu-actions.json`.
The browser rechecks current scope and other modals, then reports actual opening
back to the chat run. Acknowledgment is distinct from selecting an action.
